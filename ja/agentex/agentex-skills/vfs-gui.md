# VFS GUI

## When to Use

- ユーザーがGUIのファイルマネージャーを要求したとき
- Agentex内のファイル構造(スキル、プラン等)を視覚的に確認・操作したいとき

## Process

1. **起動コマンドの受け取りと検証**
   1. ユーザーから「/vfs --gui」等の起動コマンドを受け取る。
   2. コマンドの形式が正しいか検証する（`/vfs --gui` または「ファイルマネージャーを起動」等の自然言語コマンド）。
   3. **フォールバック**: コマンド形式が不正な場合、「`/vfs --gui` で起動できます」と正しいコマンド形式を案内する。

2. **VFSデータの収集**
   1. 現在のVFS内のファイル・フォルダ構造（skills, plans, drive 等）を走査・取得する。
   2. 各エントリの `type`（`'dir'` または `'file'`）を判定し、ディレクトリの場合は `children` を再帰的に構築する。
   3. **フォールバック**: VFSデータの取得に失敗した場合、空の初期構造（`skills: {}, plans: {}, drive: {}`）でGUIを起動し、「データの読み込みに失敗しました」と通知する。

3. **CanvasによるGUI生成**
   1. 知識(テンプレート)の `vfs-gui-template.tsx` のコードをそのまま利用して、Canvasにプレビュー(GUI)を生成する。
   2. `INIT_VFS` オブジェクトに収集したファイル構造データを設定する。
   3. **フォールバック**: テンプレートの読み込みに失敗した場合、テキストベースのディレクトリツリーを出力する。

4. **データの同期・更新**
   1. 初回実行時、および以降のファイル(スキル、プラン等)の変更・追加・削除が行われるたびに、Canvas内の `INIT_VFS` を更新し同期する。
   2. 更新は差分のみを反映し、Canvas全体の再描画は行わない。
   3. **フォールバック**: `INIT_VFS` の更新に失敗した場合、ユーザーに「データの同期に失敗しました。再度 `/vfs --gui` を実行してください」と案内する。

## Guidelines

- **厳格なコード保持**: `vfs-gui-template.tsx` のコードをそのまま利用し、`INIT_VFS` オブジェクト**以外**の書き換え・編集は一切行わないでください。
- **再生成の禁止と高速化**: 一度Canvasを生成した後は、描画にかかる時間を削減するため、Canvasの新規作成は行わず、既存のCanvasの `INIT_VFS` のみを更新してください。
- **データ同期の徹底**: VFS内のフォルダやファイルに変更があった場合は、必ず `INIT_VFS` に最新の構造を記載してください(初回実行時も必ず行うこと)。
- **入力バリデーション**:
  - `INIT_VFS` の各エントリは `type` フィールド（`'dir'` または `'file'`）が必須。不明な場合は `'file'` をデフォルトとする。
  - ディレクトリ（`type: 'dir'`）の `children` は空オブジェクト `{}` 以上であること。`null` や `undefined` は空オブジェクトに正規化する。
  - ファイル名に使用不可の文字（`/ \ : * ? " < > |`）が含まれる場合、表示時にエスケープ処理を行う。
  - ネストの深さは最大10階層とし、超過分は「...」で省略表示する。
- **コマンドエラー時の挙動ルール**:
  - **不正なコマンド形式**: `/vfs` のみ（オプションなし）で実行された場合、GUIは起動せず「`--gui` オプションを付けてください」と案内する。ただし、自然言語での起動要求（「ファイルマネージャーを開いて」等）は正常なトリガーとして処理する。
  - **存在しないパスへのアクセス**: Canvas内でユーザーが存在しないファイル/フォルダパスを操作しようとした場合、赤色のエラー表示で「指定されたパスは存在しません」と表示し、操作を無視する（クラッシュさせない）。
  - **権限エラー**: ファイルの読み取り/書き込み権限がない場合、「アクセス権限がありません」と表示し、該当項目をグレーアウトする。
  - **同時操作の競合**: 複数の操作が同時に `INIT_VFS` を更新しようとした場合、先に到達した操作を優先し、後続の操作はキューイングして順次処理する。
  - **Canvas通信エラー**: `INIT_VFS` の更新通信がタイムアウトした場合、3秒後に自動リトライ（最大2回）。解決しない場合はユーザーに手動リフレッシュを案内する。
- **禁止事項**:
  - `vfs-gui-template.tsx` のテンプレートコード（`INIT_VFS` 以外の部分）を改変してはならない。
  - Canvas上でのファイル操作（作成・削除・移動）をユーザーの確認なしに自動実行してはならない。
  - VFS外のシステムファイルやOSレベルのファイルシステムにアクセスしてはならない。
  - `INIT_VFS` に循環参照（ディレクトリが自身を子として含む）を設定してはならない。

## Decision Examples

| # | ユーザー入力 | AIの判断 | 理由 |
|---|---|---|---|
| 1 | 「/vfs --gui」 | スキル発動 → VFS GUIをCanvasに生成 | 明示的なGUI起動コマンドに合致 |
| 2 | 「ファイルマネージャーを開いて」 | スキル発動 → VFS GUIをCanvasに生成 | 自然言語でのGUIファイルマネージャー起動要求として認識 |
| 3 | 「/vfs ls skills/」 | スキル不発動 → コマンドラインベースでskillsの一覧を出力 | GUIを伴わないコマンドベースの操作であり、negative_trigger に該当 |
| 4 | 「スキルファイルの一覧を見たい」 | スキル不発動 → テキストベースでスキルファイル一覧を出力 | 「GUIで」という指定がないため、テキスト出力として処理。ただしユーザーの意図が不明確な場合は「GUIで表示しますか？」と確認してもよい |
| 5 | 「/vfs」（オプションなし） | スキル不発動 → 「`--gui` オプションを付けてください」と案内 | コマンドエラー時の挙動ルールに従い、不正なコマンド形式として処理 |

## Error Handling

| # | エラーケース | 原因 | 対処法 |
|---|---|---|---|
| 1 | テンプレートファイルが見つからない | `templates/vfs-gui-template.tsx` が存在しないか、パスが不正 | ユーザーにテンプレート不在を通知し、テキストベースのディレクトリツリーを出力する |
| 2 | VFSデータの走査失敗 | ディレクトリの読み取り権限がない、またはファイルシステムエラー | 空の初期構造でGUIを起動し、「一部のデータを読み込めませんでした」と通知する |
| 3 | `INIT_VFS` への循環参照の混入 | ディレクトリが自身を子として含むデータ構築バグ | 循環参照を検出した時点で該当ノードを除外し、警告メッセージを表示する |
| 4 | Canvas更新の通信タイムアウト | ネットワーク遅延またはCanvasの応答遅延 | 3秒後に自動リトライ（最大2回）。解決しない場合は「手動リフレッシュしてください」と案内 |
| 5 | ファイル/フォルダ名の文字化け | ファイル名にUTF-8非対応の文字が含まれている | 表示時にUTF-8にエンコードし、変換不可の文字は `?` に置換して表示する |
| 6 | 存在しないパスへの操作要求 | ユーザーが削除済みまたは未作成のパスを指定 | 「指定されたパスは存在しません」とエラー表示し、操作を無視する |

## Data Structure

更新対象の `INIT_VFS` は以下の構造に従ってください：

```javascript
const INIT_VFS: Record<string, VFSNode> = {
  skills: { type: 'dir', children: {} },
  plans:  { type: 'dir', children: {} },
  drive:  { type: 'dir', children: {} }
};
```
