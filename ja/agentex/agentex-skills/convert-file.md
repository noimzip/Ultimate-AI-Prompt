# ファイル形式・フォーマット変換

## When to Use

- ユーザーがファイル形式(フォーマット)を変換して新しいファイルを作成したいとき
- 表データやテキストデータの構造を別の言語・フォーマット(CSV ↔ JSON ↔ Markdown等)に変換したいとき

## Process

1. **入力ファイルの受け取りと検証**
   1. ユーザーから対象のファイル（画像、PDF、ドキュメント、テキスト、CSVなど）またはデータを受け取る。
   2. ファイルの拡張子と実際の内容が一致しているか確認する（例: `.csv` と名付けられていても中身がJSON形式ではないか等）。
   3. ファイルが空、または読み取り不能な場合は「ファイルの内容を読み取れませんでした。別の形式で再アップロードしてください」と案内する。
   4. **フォールバック**: ファイル形式が判定不能な場合、ユーザーに「このファイルの形式を教えてください」と確認する。

2. **変換先フォーマットの確認**
   1. ユーザーの指示から変換先の形式（拡張子）を特定する。
   2. 変換元→変換先のペアがサポート対象か確認する（下記「サポート変換ペア」テーブル参照）。
   3. **フォールバック**: サポート対象外の変換ペアの場合、代替フォーマットを提案する（例:「.xlsx への直接変換はできませんが、CSV形式で出力できます」）。

3. **フォーマット変換と整形**
   1. 指定されたフォーマット（変換先）の構造に合わせて、ファイルの内容を抽出・整形・変換する。
   2. 変換中にデータ欠損や型の不一致が発生した場合は、影響範囲をユーザーに通知する。
   3. 構造化データ（CSV、JSON等）の場合は、エンコーディング（UTF-8）を維持する。

4. **出力ファイルの生成と提示**
   1. 変換後のデータを、AgentexのVFS（仮想ファイルシステム）上に新規ファイル（指定された拡張子）として作成するか、コードブロックとしてユーザーに提示する。
   2. 出力ファイルのサイズが大きい場合（目安: 500行超）は、先頭部分をプレビュー表示し全体はファイルとして保存する。
   3. 変換結果の概要（行数、カラム数、変換の注意点等）をユーザーに報告する。

## Guidelines

### 基本ルール
- **テキストベースの出力に限定すること**: AI（Gemini）は `.pdf`、`.docx`、`.xlsx` などのバイナリファイルを直接生成・出力することはできません。出力先は必ず `.txt`, `.md`, `.csv`, `.json`, `.html`, `.js` などのテキストベースのフォーマットにしてください。
- ユーザーがバイナリ形式（例: Excel形式）を求めた場合は、「Geminiの仕様上CSV形式での出力になります」等と説明し、代替フォーマットで提供してください。
- 単なる拡張子のリネーム（例: `data.txt` を `data.md` に変えるだけ）ではなく、内容のフォーマット変換を伴うべきかを判断し、必要に応じて構造を整形してください（例: カンマ区切りテキストをMarkdownテーブルに変換するなど）。

### 入力バリデーションルール
- **エンコーディング確認**: 入力ファイルがUTF-8でない場合（Shift_JIS等）、変換時に文字化けが起きないよう注意し、必要に応じてユーザーに確認する。
- **ファイルサイズ上限**: 極端に大きなファイル（1万行超）の場合は、処理可能な範囲に分割するか、ユーザーに絞り込みを提案する。
- **ヘッダー行の判定**: CSVやTSVの場合、1行目がヘッダーかデータかを内容から判定し、ユーザーに確認を求める。

### 禁止事項
- バイナリ形式（`.docx`, `.xlsx`, `.pdf`, `.pptx`）の直接出力
- 元データの内容を勝手に削除・改変すること（フォーマット変換以上の変更は行わない）
- ユーザーの指示なくファイル名やパスを変更すること

## サポート変換ペア

以下は本スキルで対応可能な主要な変換元→変換先の組み合わせです。

| # | 変換元 | 変換先 | 備考 |
|---|---|---|---|
| 1 | CSV (`.csv`) | JSON (`.json`) | 各行をオブジェクトの配列に変換。ヘッダー行をキーとして使用 |
| 2 | CSV (`.csv`) | Markdown (`.md`) | Markdownテーブル形式に変換 |
| 3 | CSV (`.csv`) | HTML (`.html`) | `<table>` タグを使用したHTMLテーブルに変換 |
| 4 | CSV (`.csv`) | TSV (`.tsv`) | 区切り文字をカンマからタブに変換 |
| 5 | JSON (`.json`) | CSV (`.csv`) | フラットなオブジェクト配列を想定。ネストは最上位キーで展開 |
| 6 | JSON (`.json`) | Markdown (`.md`) | 配列→テーブル、オブジェクト→定義リスト形式に変換 |
| 7 | JSON (`.json`) | YAML (`.yaml`) | 構造をそのまま維持してYAML形式に変換 |
| 8 | Markdown (`.md`) | HTML (`.html`) | Markdown記法をHTML要素に変換 |
| 9 | Markdown (`.md`) | テキスト (`.txt`) | 記法を除去したプレーンテキストに変換 |
| 10 | TSV (`.tsv`) | CSV (`.csv`) | 区切り文字をタブからカンマに変換 |
| 11 | テキスト (`.txt`) | Markdown (`.md`) | 見出しやリスト構造を推定してMarkdown化 |
| 12 | テキスト (`.txt`) | CSV (`.csv`) | 区切り文字（カンマ、タブ等）を検出して構造化 |
| 13 | HTML (`.html`) | Markdown (`.md`) | HTMLタグをMarkdown記法に変換 |
| 14 | YAML (`.yaml`) | JSON (`.json`) | 構造をそのまま維持してJSON形式に変換 |
| 15 | XML (`.xml`) | JSON (`.json`) | XML要素をJSONオブジェクトにマッピング |

> **注意**: 上記以外の変換ペアについてはユーザーの要求に応じて可能な範囲で対応しますが、バイナリ形式への変換は非対応です。

## Decision Examples

| # | ユーザー入力 | AIの判断 | 理由 |
|---|---|---|---|
| 1 | 「このCSVファイルをJSON形式にして」 | スキル発火 → CSV読み取り → JSON配列に変換 → VFS保存 | テキストベース間の明確なフォーマット変換要求 |
| 2 | 「data.txt を data.md にリネームして」 | **発火しない** → VFSリネーム機能へリダイレクト | 内容のフォーマット変換を伴わない単純なリネーム要求 |
| 3 | 「このテキストファイルをExcel形式にして」 | スキル発火 → CSV形式で代替出力を提案 | バイナリ出力不可のため代替提案し、同意を得てCSV変換 |
| 4 | 「JSONのデータをMarkdownのテーブルで表示して」 | スキル発火 → JSONをパース → Markdownテーブル生成 | JSON→Markdown(テーブル)の構造変換要求 |
| 5 | 「このHTMLページをテキストに変換して」 | スキル発火 → HTMLタグ除去 → プレーンテキスト出力 | HTML→テキストの明確な変換要求 |

## Error Handling

| # | エラーケース | 検出方法 | 対処法 |
|---|---|---|---|
| 1 | 入力ファイルが空 | ファイルサイズが0バイト、または全行が空白 | 「ファイルが空です。内容を確認して再アップロードしてください」と案内 |
| 2 | CSVのカラム数が行ごとに不一致 | パース時に各行の列数を比較 | 最大カラム数に合わせて不足分を空文字で補完し、「一部の行でカラム数が異なっていたため補完しました」と通知 |
| 3 | JSONの構文エラー | `JSON.parse()` 失敗 | エラー箇所（行番号）を特定し、「JSON構文エラーが行Nで検出されました。修正してください」と案内 |
| 4 | 文字コードの不一致（文字化け） | 出力に非ASCII文字の欠損や置換文字が含まれる | 「文字化けの可能性があります。元ファイルのエンコーディングがUTF-8か確認してください」と案内 |
| 5 | 非対応の変換ペアを要求 | 変換先がバイナリ形式（`.xlsx`, `.pdf`等） | 「この形式への直接変換は対応していません。代わりに〇〇形式で出力できますが、よろしいですか？」と代替提案 |
| 6 | ファイルサイズ超過（1万行超） | 行数カウント | 「ファイルが非常に大きいため、最初の1000行を変換しました。全体の変換が必要な場合はお知らせください」と分割対応 |
| 7 | ネストが深いJSONの展開失敗 | ネスト深度が5階層超 | 「JSONのネストが深いため、上位2階層のみを展開しました」と部分展開結果を提示 |
